PWN 2

基础知识点

  • ==system(“/bin/sh”)的工作原理==：
    • system()函数先调用fork（）系统调用。
    • 创建一个子进程，原进程作为父进程继续运行，其中子进程负责交互，父进程负责回收
    • 在这个子进程中调用/bin/sh -c来执行command指定的命令。
      • -c选项是告诉shell从字符串command中读取要执行的命令（shell将扩展command中的任何特殊字符）
    • /bin/sh在系统中一般是个软链接，指向dash或者bash等常用的shell解释器，

    • 父进程则调用waitpid()系统调用来为变成僵尸的子进程收尸，获得其结束状态，然后将这个结束状态返回给system()函数的调用者

PWN 26 27 28

基础知识点

  • ==ASLR随机化==：

    • 将libc，栈，堆，mmap，共享库的基址随机

    • 内存布局随机化： ASLR的主要目标是随机化程序的内存布局。在传统的内存布局中，不同的库和模块通常会在固定的内存位置上加载，攻击者可以利用这种可预测性来定位和利用漏洞。ASLR通过随机化这些模块的加载地址，使得攻击者无法准确地确定内存中的关键数据结构和代码的位置。

    • 地址空间范围的随机化： ASLR还会随机化进程的地址空间范围。在传统的地址空间中，栈、堆、代码段和数据段通常会被分配到固定的地址范围中。ASLR会随机选择地址空间的起始位置和大小，从而使得这些重要的内存区域在每次运行时都有不同的位置。

    • 随机偏移量： ASLR会引入随机偏移量，将程序和模块在内存中的相对位置随机化。这意味着每个模块的实际地址是相对于一个随机基址偏移的，而不是绝对地址。攻击者需要在运行时发现这些偏移量，才能准确地定位和利用漏洞。模块内部地址之间的偏移量不会随机

    • 堆和栈随机化： ASLR也会对堆和栈进行随机化。堆随机化会在每次分配内存时选择不同的起始地址，使得攻击者无法准确地预测堆上对象的位置。栈随机化会随机选择栈帧的起始位置，使得攻击者无法轻易地覆盖返回地址或控制程序流程。

    • 开启等级：0 1 2

    • 指令

      • echo 0 > /proc/sys/kernel/randomize_va_space 将0打印到保存开启等级的地方
        • 临时设置
      • cat /proc/sys/kernel/randomize_va_space 查看保护等级

PWN 31

基础知识点

  • PIE保护：随机化主程序基址，不干涉外部的库的地址
    • 配合ALSR保护，将外部库也随机化
    • 在PIE编译时，所有段的虚拟地址都是在基址为0下给出的
    • 在32位下由于开启PIE保护，需要一个寄存器作为got表的指针即EBX
      • 函数入口通过 call __x86.get_pc_thunk.bx ; add ebx, 0x1fc0 这样的代码将 ebx 调整为指向 .got 段起始地址。其中立即数 0x1fc0 就是 VMA，是编译时计算出来的固定距离。
    • 因此在这个保护下我们想使用plt或者got表中的函数，必须保证ebx的值为got指针，不能直接覆盖
  • 调用程序自身函数用sym，外部用plt

解题过程

  1. 日常查看保护

  • 开启了PIE保护，基址改变，无法直接调用函数了

  1. 这一道题目和上面题目在反编译中多给了一个main函数真实地址

    • 实际上我以为main函数就是基址，但是应该用main’真实地址-其sym
      • 在PIE保护开启下，用plt和got获取的都是固定偏移

  2. 这样我们知道基址后面可能会很好写

  3. 然而因为开启了PIE保护，在32位下调用got表时，EBX需要保持为一个数字，即got段的地址，这个地址是由got表在ELF的位置决定，通常为相对程序基址加上程序基址

    • 怎么找到这个相对程序基址的偏移呢，用objdump -h，查找所有的段

      • 列 值 含义
        Idx 21 段索引号
        Name .got 段名称，这里表示全局偏移表（Global Offset Table）
        Size 00000040 段在内存中的大小（十六进制），这里是 64 字节
        VMA 00001fc0 虚拟内存地址（Virtual Memory Address），即段在运行时的起始地址，基址为 0 时
        LMA 00001fc0 加载内存地址（Load Memory Address），在 Linux 下通常与 VMA 相同
        File off 00000fc0 段在文件中的偏移量（即从文件开始到该段数据的字节偏移）
        Algn 2**2 对齐方式，2**2 即 2^2 = 4 字节对齐

  4. 然后就势如破竹

  • 最后我还学到个新东西，可以在一定位置加上print来打印出求得的东西来观察程序在哪崩溃的

  • ==alpha3==
    • 只能使用python2环境运行
    • 基本用法：python ALPHA3.py –input=”input_file” –output=”output_file”
    • 参数说明
      • architecture：目标处理器架构，例如 x86 或 x64。
      • character encoding：字符编码方式，例如 ascii。
      • casing：字符大小写，例如 uppercase（大写字母）或 mixedcase（大小写混合）。
      • base address：用于 shellcode 重定位的寄存器，例如 eax 或 rax。
      • –input：输入文件路径，包含待编码的普通 shellcode。
      • –output：输出文件路径，保存生成的 alphanumeric shellcod
    • 里面代码很多asm的要用nasm编译为bin可执行的
  • /tmp装临时缓存数据，机器重启后消失

  3. 将下载的文件传输到ubuntu中去，使用这个工具需要一个简单的shellcode作为底子，因此要事先编译一个文件，这里使用命令echo -ne “\x48\x31\xf6\x56\x48\xbf\x2f\x62\x69\x6e\x2f\x2f\x73\x68\x57\x54\x5f\x6a\x3b\x58\x99\x0f\x05” > /tmp/sc.bin
  4. 然后环境必须使用==python2==才可以，然而我的ubuntu版本不支持下载这个
  5. 下载==conda==，创建一个有python2的虚拟环境
  6. 发现其中没有rax.bin只有rax.asm，于是使用==nasm==进行编译
  7. 最终执行命令，获取纯编码shellcode

  • ==流程思路==

    • NX保护没有开启导致栈堆可写
      • 可以手写汇编然后asm
    • 由于只能写入56个字符，要填充40个字节，因此要构建一个曲回针样式的结构
      • 总共有三个要执行的代码块，一块放在溢出后的16个字节，一块放在填充区域的40个字节，最后一块放在mmap
        • 第一块放入p64(jmp_rsp)+asm(“sub rsp,0x30; jmp rsp”)，让程序流程指向较大的填充字节处
        • 第二块填充字节则可以构建代码，让程序流程指向mmap地址处
        • 第三块mmap则构建orw，对文件进行读取打印，这个流程需要一个缓冲区域有写入和执行功能，用这个来作为跳板
          • read和wirte不能单独完成硬件到硬件的写入（磁盘到终端）
